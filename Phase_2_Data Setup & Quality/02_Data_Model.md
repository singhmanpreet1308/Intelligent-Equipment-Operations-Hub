### Table: sites

**Purpose:**  
Stores master data for each operational site where equipment/assets are located.

| Column | Data Type | Key | Description |
|---|---|---|---|
| Site_ID | String | Primary Key | Unique identifier for each site |
| Site_Name | String |  | Name of the operating site |
| Location | String |  | Geographic location of the site |
| Region | String |  | Operational region |
| Site_Type | String |  | Type of facility/site |
| Operational_Status | String |  | Current site status |
| Commission_Date | Date |  | Date the site became operational |

### Example Records

| Site_ID | Site_Name | Location | Region | Site_Type | Operational_Status |
|---|---|---|---|---|---|
| SITE001 | Belfast Operations Plant | Belfast | Northern Ireland | Manufacturing | Active |
| SITE002 | Larne Equipment Centre | Larne | Northern Ireland | Industrial | Active |
| SITE003 | Dublin Operations Hub | Dublin | Ireland | Distribution | Active |

### Business Rules

- `Site_ID` must be unique.
- `Site_ID` cannot be null.
- Only active sites should generate operational sensor data.
- Every asset must belong to one valid `Site_ID`.

### Table: assets

**Purpose:**  
Stores master information for each equipment asset operating across the sites.

| Column | Data Type | Key | Description |
|---|---|---|---|
| Asset_ID | String | Primary Key | Unique identifier for each asset |
| Site_ID | String | Foreign Key | Links the asset to `sites.Site_ID` |
| Asset_Name | String |  | Human-readable equipment name |
| Asset_Type | String |  | Equipment category/type |
| Manufacturer | String |  | Equipment manufacturer |
| Model | String |  | Manufacturer model number |
| Serial_Number | String | Unique | Unique equipment serial number |
| Install_Date | Date |  | Date equipment was installed |
| Criticality | String |  | Business criticality: High / Medium / Low |
| Rated_Capacity | Decimal |  | Designed operating capacity |
| Capacity_Unit | String |  | Unit for rated capacity |
| Asset_Status | String |  | Current status: Active / Maintenance / Offline |
| Expected_Life_Years | Integer |  | Expected useful operational life |
| Warranty_End_Date | Date |  | Warranty expiry date |

### Example Records

| Asset_ID | Site_ID | Asset_Name | Asset_Type | Manufacturer | Model | Criticality | Asset_Status |
|---|---|---|---|---|---|---|---|
| AST0001 | SITE001 | Air Compressor 01 | Compressor | Atlas Copco | GA30 | High | Active |
| AST0002 | SITE001 | Cooling Pump 01 | Pump | Grundfos | CR15 | Medium | Active |
| AST0051 | SITE002 | Conveyor Motor 01 | Motor | Siemens | SIMOTICS GP | High | Active |
| AST0101 | SITE003 | Cooling Fan 01 | Fan | ABB | AXIAL-500 | Low | Active |

### Business Rules

- `Asset_ID` must be unique and cannot be null.
- Every `Site_ID` must exist in the `sites` table.
- `Serial_Number` should be unique.
- `Install_Date` cannot be later than the operational data date.
- `Criticality` must be one of:
  - High
  - Medium
  - Low
- `Asset_Status` must be one of:
  - Active
  - Maintenance
  - Offline
- Only assets with valid master records should appear in sensor, maintenance, failure, or work-order datasets.
- An asset belongs to only one site at a given point in time.

### Project Volume

- 3 Sites
- 50 Assets per Site
- **150 Assets Total**

This provides enough scale to demonstrate Fabric ingestion, transformation, analytics, Power BI modelling, Power Apps, Power Automate, and AI use cases without creating unnecessary data volume.

  ### Table: sensor_readings

**Purpose:**  
Stores timestamped operational readings generated by equipment sensors.

| Column | Data Type | Key | Description |
|---|---|---|---|
| Reading_ID | String | Primary Key | Unique identifier for each sensor reading |
| Asset_ID | String | Foreign Key | Links to `assets.Asset_ID` |
| Timestamp | DateTime |  | Date and time when the reading was captured |
| Temperature_C | Decimal |  | Equipment operating temperature in °C |
| Vibration_mm_s | Decimal |  | Equipment vibration level |
| Pressure_Bar | Decimal |  | Operating pressure |
| Power_Consumption_kW | Decimal |  | Equipment power consumption |
| RPM | Integer |  | Rotational speed |
| Load_Pct | Decimal |  | Percentage of rated operating load |
| Health_Score | Decimal |  | Derived equipment health score from 0–100 |
| Operating_State | String |  | Current operating condition |
| Anomaly_Flag | Boolean |  | Indicates whether the reading is abnormal |

### Example Records

| Reading_ID | Asset_ID | Timestamp | Temperature_C | Vibration_mm_s | Pressure_Bar | Power_Consumption_kW | RPM | Load_Pct | Health_Score | Operating_State | Anomaly_Flag |
|---|---|---|---:|---:|---:|---:|---:|---:|---:|---|---|
| RDG000001 | AST0001 | 2026-06-01 08:00 | 68.4 | 2.3 | 7.1 | 24.8 | 1480 | 72.0 | 94.0 | Running | False |
| RDG000002 | AST0001 | 2026-06-01 09:00 | 69.1 | 2.5 | 7.0 | 25.2 | 1490 | 74.0 | 92.0 | Running | False |
| RDG000003 | AST0002 | 2026-06-01 08:00 | 81.2 | 5.9 | 5.8 | 31.7 | 1420 | 89.0 | 61.0 | Warning | True |

### Business Rules

- `Reading_ID` must be unique.
- Every `Asset_ID` must exist in the `assets` table.
- `Timestamp` cannot be null.
- Sensor values must remain within realistic engineering ranges.
- `Load_Pct` should normally remain between 0 and 100.
- `Health_Score` must remain between 0 and 100.
- `Anomaly_Flag = True` when one or more readings breach defined operating thresholds.
- Equipment marked `Offline` should not generate normal running sensor readings.
- Sensor values should vary realistically over time rather than being purely random.

### Operating States

Allowed values:

- Running
- Idle
- Warning
- Critical
- Offline

### Project Data Volume

- Hourly readings

### Table: costs

**Purpose:**  
Stores maintenance and failure-related cost records for each asset and work order.

| Column | Data Type | Key | Description |
|---|---|---|---|
| Cost_ID | String | Primary Key | Unique identifier for each cost record |
| Asset_ID | String | Foreign Key | Links to `assets.Asset_ID` |
| WorkOrder_ID | String | Foreign Key / Nullable | Related work order |
| Maintenance_ID | String | Foreign Key / Nullable | Related maintenance event |
| Failure_ID | String | Foreign Key / Nullable | Related failure event |
| Cost_Date | Date |  | Date when the cost was recorded |
| Cost_Type | String |  | Category of cost |
| Labour_Cost | Decimal |  | Technician/labour cost |
| Parts_Cost | Decimal |  | Spare-parts cost |
| Contractor_Cost | Decimal |  | External contractor/service cost |
| Downtime_Cost | Decimal |  | Estimated financial impact of equipment downtime |
| Other_Cost | Decimal |  | Other related operational costs |
| Total_Cost | Decimal | Derived | Total cost of the event |
| Currency | String |  | Currency used for cost reporting |

### Derived Calculation

`Total_Cost = Labour_Cost + Parts_Cost + Contractor_Cost + Downtime_Cost + Other_Cost`

### Example Records

### Cost Types

Allowed values:

- Preventive Maintenance
- Corrective Maintenance
- Emergency Repair
- Inspection
- Component Replacement
- Downtime Loss

### Business Rules

- `Cost_ID` must be unique.
- Every `Asset_ID` must exist in the `assets` table.
- Foreign keys must exist when populated.
- Cost values cannot be negative.
- `Total_Cost` must be derived rather than manually generated independently.
- Emergency and critical failures should generally result in higher total cost.
- Preventive maintenance should generally have lower downtime cost.
- Currency should remain consistent for portfolio reporting.
